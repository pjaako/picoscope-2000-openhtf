# AGENTS.md

OpenHTF plug for PicoScope 2000 Series (A API) USB oscilloscopes (developed against a 2207B MSO). Read `SPEC.md`; it is the contract.

- The only source of truth for driver API details is `docs/api_reference.md`, transcribed from `docs/picoscope-2000-series-a-api-programmers-guide.pdf` (ps2000apg.en-12; greppable dump in the `.txt` next to it). Never use a function, argument order, enum name or behaviour from another Pico series, from `pico-python`, from picosdk example scripts or from memory. If something you need is not in that file, stop and say so. Status-code names come from `picosdk.constants.PICO_STATUS`, which mirrors `PicoStatus.h`, the file the manual designates (§4.1).
- Every driver call, enum name and constant in `src/` carries a manual citation comment, `# PG §3.39`. Behaviour the manual leaves open is marked `# ASSUMPTION(hw): ...` in the source and implemented the same way in the fake. `docs/api_reference.md` ends with the list of open questions; hardware acceptance resolves them one by one, each answer goes into README "Things the manual does not tell you", and the fake is corrected to match.
- Coder agents never touch a real oscilloscope and never install the native driver; they use `picoscope_2000_openhtf.fake_resource.FakePs2000a`. Only the project-owner agent runs hardware, on the user's local Linux machine, with the user informed. Driving code always stops and closes the unit in `finally:`/`tearDown()`.
- `picosdk.ps2000a` raises at import time when the native library is missing. Only `driver.py` may import it, lazily, inside the class that wraps it. `tests/test_import.py` enforces this; keep it green.
- Hardware-free is mandatory: `uv run pytest -q`, `uv run python example_test.py --fake`, `uv run ruff check .`, `uv run ruff format --check .` and `uv run mypy` must stay clean on a machine without PicoSDK. CI is plain ubuntu.
- The plug is thin and data-centred, like https://github.com/pjaako/rigol-dho-openhtf: capture conditions are a frozen `Capture` dataclass, the plug exposes `apply_capture`, `single`, `wait_ready`, `read_waveform`, `stop`; a `Waveform` holds the untouched ADC counts plus the metadata needed to recompute time and volts. Measurements are pure numpy functions in `measure.py`, never in the plug. No setter per setting.
- Store `raw` plus `meta`, never float arrays. Validate the count-to-volt conversion against a signal whose amplitude is known (the fake's clock, and a generator on hardware). Refuse clipped data where a verdict depends on it.
- Nothing on a scope input is dangerous for the DUT, but `tearDown()` must still stop any running capture and close only the handle this plug opened. It is idempotent, never raises, and after it every method raises `RuntimeError("plug closed")`.
- Several PicoScopes share one machine. Tests and tools open a unit by serial number; `None` (first unit found) is allowed but logs a warning when more than one unit is enumerated. Never hard-code a serial; hardware tools take it from the environment variable `PICOSCOPE_SERIAL`.
- Set OpenHTF config keys after importing the plug module (`CONF.load(...)` before the key is declared is lost).
- Python 3.13, package in `src/picoscope_2000_openhtf/`, `uv sync --all-extras --dev`. Do not add dependencies beyond `pyproject.toml`. Supported platforms are whatever picosdk loads the library on (Windows, Linux, macOS); README documents the native-driver install for all three, with Linux x86 as the tested one.
- A fake instrument only knows what we told it (lesson from rigol-dho-openhtf and siglent-sdg-openhtf: hardware acceptance found defects fake-based tests could not). Every feature gets a run on hardware before it is called done, and each finding goes back into the fake, made at least as strict as the real device.
- File and module naming mirrors the sibling repos (`SPEC.md`, `AGENTS.md`, `HANDOFF.md`, `capture.py`, `fake_resource.py`, `example_test.py`, `tools/probe.py`, `tests/test_plug.py`) so agents can move between them. Shared code is not extracted into a common package.
- This repository is public. Serial numbers in text are placeholders (`FAKE0/001`); real serials, private dumps (`dumps/`) and machine paths stay out of git.
- Git: develop on the branch the session was given, commit with a descriptive message prefixed by the task id from `HANDOFF.md` (`T3: ...`), and end every commit message with the trailers the harness provides (`Co-Authored-By:` and `Claude-Session:`). Do not put model identifiers anywhere else in the repository.
- Roles: the project-owner agent writes specs, delegates coding to cheaper agents (Sonnet class), has the result reviewed by a stronger agent where it matters, and keeps `SPEC.md`, `AGENTS.md`, `HANDOFF.md`, `README.md` and `docs/` current enough that a cold agent can take over at any commit. `docs/research.md` records why this project exists and what it borrows from.
- Status for a cold agent is in `HANDOFF.md`: what is done, what is in flight, what is blocked on hardware, the task board.
